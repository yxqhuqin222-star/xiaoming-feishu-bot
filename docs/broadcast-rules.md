# 小明播报规则

## 来源说明

本规则从 `jump` 项目的日常播报能力迁移而来。

原项目路径：

```text
/Users/kityhello/workplace/project/work/jump
```

迁移原则：

- 只迁移播报内容规则、时间规则、去重规则和互动命令。
- 不迁移钉钉 webhook、钉钉签名、钉钉关键词等通道实现。
- 新项目统一按飞书机器人“小明”发送和回复。

## 播报通道变化

旧链路：

```text
生成播报内容
→ 通过钉钉 webhook 发送到钉钉群
```

新链路：

```text
生成播报内容
→ 通过飞书开放平台机器人“小明”发送到飞书会话或群聊
```

注意：

- 飞书群聊播报应使用飞书机器人发消息能力，不使用钉钉 webhook。
- 如果是群聊互动回复，默认必须用户 @小明；未 @ 的普通群消息不触发回复。
- 原来的 `dingtalk_keyword` 在飞书里不再作为安全关键词使用；如果仍需要消息前缀，应改名为 `message_prefix`。
- “早安，冯驰”和“驰子，...”属于称呼配置，应分别使用 `recipient_name` 和 `closing_name`，不要和消息前缀混用。

## 默认播报日程

| 类型 | 时间 | 默认开启 | 说明 |
| --- | --- | --- | --- |
| 早安 | 10:00 | 是 | 天气、提醒、心理学冷知识或假期提醒、今日摘抄 |
| 三分钟知识卡 | 11:40 | 是 | 工作日知识卡，优先使用动态库存 |
| 午间新闻 | 12:00 | 否 | AI Signal 摘要 |
| 大道消息 | 16:30 | 是 | 即刻精选 / Owen Links / 微信公众号 / 内容订阅 |
| 摸鱼日历 | 17:30 | 是 | 距下班、距周末和五个轻量互动模块 |
| 晚间收尾 | 19:00 | 是 | 晚间摘抄和下班文案 |

规则：

- 默认只在工作日自动发送。
- 手动发送“大道消息”时允许周末运行。
- `due` 模式只发送当前时间之前、当天尚未发送过的播报。
- 每类播报每天最多自动发送一次。

全局内容去重：

- 所有模块每天变化的正文、摘抄、知识卡、问题、文案和资讯链接均写入统一历史记录。
- 发送前同时检查模块自身记录和统一历史记录；任何历史已发送内容都必须跳过。
- 大道消息跨即刻、Owen Links、微信公众号和内容订阅按正文或原文 URL 去重。
- 固定标题、称呼、天气、日期、距离下班和距离周末等结构字段不参与内容去重。
- 可用新内容不足时取消对应模块，不使用历史内容补位。

## 早安

内容结构：

```text
早安，冯驰。
天气：...
今日提醒 / 假期雷达 / 心理学冷知识：...
今日摘抄：
1. ...
2. ...
3. ...
```

规则：

- 天气优先取配置或实时天气；失败时使用“天气：暂时无法获取”。
- 如果配置了当天提醒，优先显示提醒。
- 如果配置了下个假期日期，显示距离假期还有几天。
- 没有提醒时，从心理学冷知识题库选一条未发送内容。
- 今日摘抄取 3 条未发送文学句子。
- 早安中的心理学冷知识需要归档到 `docs/心理学冷知识.md`。

去重：

- 心理学冷知识按规范化正文 SHA-256 去重。
- 文学摘抄按正文 SHA-256 去重。

## 三分钟知识卡

内容结构：

```text
三分钟知识卡｜...
...
```

规则：

- 只在工作日发送。
- 优先从动态知识卡库存中选择内容。
- 没有动态卡时，按工作日节奏轮换本地主题卡。
- 单条知识卡长度应保持在 250-400 字之间。
- 每条知识卡必须有可验证来源 URL。
- 库存低于阈值时应提示补充。
- 发送后归档到 `docs/三分钟知识卡.md`。

去重：

- 按主题槽位、日期和内容三类键共同去重。
- 动态卡发送后要标记为已发送。

## 午间新闻

内容结构：

```text
午间新闻
AI Signal｜X ... 条，播客 ... 期，论文 ... 篇。

**AI 产品 / 商业 / 趋势**
1. 来源：标题
看点：...
链接

**投资模块**
...

**今天最值得跟的 3 条线**
1. 产品/趋势：...
2. 投资/基建：...
3. 继续跟踪：...
```

规则：

- 默认关闭，需在配置里启用。
- 来源为 AI Signal 生成结果。
- 可按用户配置跳过论文等低优先级来源。
- 没有符合口径的新内容时，发送“今天暂无符合已确认口径的新内容。”
- 发送成功后需要标记 AI Signal delivery mark，避免重复投递。

## 大道消息

默认来源：即刻精选。

来源选项：

- `jike`：即刻精选。
- `owen`：Owen Links。
- `wechat`：微信公众号 RSS。
- `feeds`：通用 RSS/Atom 内容订阅。

### 即刻精选

读取规则：

- 必须使用用户已登录的 Chrome 页面读取。
- 目标地址：

```text
https://web.okjike.com/topic/63579abb6724cc583b9bba9a/selected
```

- 选择前 10 条未发送内容。
- 对目标卡片做精准 DOM 提取。
- 不使用整页截图或连续滚动作为最终依据。
- 必须取得作者、时间、完整正文和真实原文链接。
- 任一字段缺失，或正文仍处于折叠状态，停止发送。

格式：

```text
大道消息｜即刻精选。
1. [作者｜时间] 正文
原文：链接
```

去重：

- 即刻精选按规范化正文 SHA-256 去重。

### Owen Links

格式：

```text
大道消息｜Owen Links。
1. 标题：摘要 链接
```

规则：

- 只有用户明确要求“Owen”或“Owen Links”时，才使用该来源。
- 即刻精选不可用且没有手动条目时，可以作为兜底来源。
- 按原文 URL 去重。

### 微信公众号

格式：

```text
大道消息｜微信公众号。
1. [公众号/作者｜发布时间] 标题
摘要
原文：链接
```

规则：

- 只有用户明确要求“微信公众号”时，才使用配置的微信公众号 RSS 来源。
- 内容按实际可用且合规的范围生成播报。
- 必须保留原文链接。
- 摘要过长时截断。
- 按原文 URL 去重。

### 通用内容订阅

格式：

```text
大道消息｜内容订阅。
1. [来源名称｜发布时间] 标题
摘要
原文：链接
```

规则：

- 用户明确要求通用内容订阅时，使用 `content_feeds`。
- 公众号和网站可以共用这个入口。
- 每个 feed 必须配置 `name` 和 `url`。
- 按原文 URL 去重。

### 大道消息发送确认

原 `jump` 规则要求：每次发送前必须展示来源和完整消息预览，获得明确确认后才调用钉钉机器人。

迁移到小明后改为：

- 每次手动发送“大道消息”前，必须展示来源和完整消息预览。
- 获得用户明确确认后，才让小明发到飞书。
- 自动定时发送只能使用已经验证过的来源，不能临时接入未验证的新来源。

## 摸鱼日历

内容结构：

```text
摸鱼日历。
距下班约 X 小时 X 分钟。
距周末还有 X 天。
情绪温度：...
办公室观察题：...
一分钟放空：...
今日小问题：...
下班通行证：...
```

规则：

- 默认 17:30 发送。
- 默认下班时间是 19:00，可配置。
- 距周末按当前工作日计算。
- 五个模块都必须出现。
- 每个模块必须有 100 条不重复文案。
- “今日小问题”从本地每日一问文档读取，要求 100 条不重复问题。

去重：

- 每个模块按正文 SHA-256 去重。
- 每次发送后记录本次选中的五个模块内容。

## 晚间收尾

内容结构：

```text
晚间收尾。
1. ...
2. ...
3. ...
驰子，...
```

规则：

- 默认 19:00 发送。
- 取 3 条未发送文学摘抄。
- 结尾从 100 条不重复下班文案中选 1 条。
- 当所有下班文案用完前，可使用里程碑文案“小猪播报100天了～！”。

去重：

- 文学摘抄按正文 SHA-256 去重。
- 下班文案按正文 SHA-256 去重。

## 群内互动命令

小明可以保留以下轻量命令：

触发前提：

- 群聊里默认必须先 @ 小明，再发送命令或问题。
- 私聊不需要 @ 小明。
- 未 @ 小明的普通群消息只记录并跳过，不调用模型、不发送兜底回复。

| 命令 | 回复规则 |
| --- | --- |
| `/答案` | 如果上一条播报有可揭晓答案，回复“答案：...”；否则提示没有可揭晓答案 |
| `/今天吃什么` | 从午餐选项里换一个建议 |
| `换一个午餐` | 同 `/今天吃什么` |
| `/投票 A vs B` | 回复已收到投票题，并请大家直接回复选项 |
| `新闻` | 如果上一条播报是大道消息，提示可回复“展开第 1 条” |
| `你会什么` / `帮助` | 简短说明当前可用能力 |

迁移到小明后的语气要求：

- 命令回复可以带小明的口语感，但要短。
- 不使用过度网络化表达。
- 不用“我记小本本上”这类网感太重的话。
- 保留直接、熟人式、轻微调侃即可。

## 飞书版格式注意事项

- 飞书文本消息支持换行，原有纯文本播报可以直接迁移。
- 飞书群聊中不要依赖钉钉安全关键词。
- 飞书 @ 人应使用飞书的 mention 结构或 lark-cli 支持的参数，不沿用钉钉手机号 @。
- Markdown 类内容要先确认飞书消息类型支持；不确定时优先发送纯文本。
- 本地图片不能直接放进消息正文；如需图片，必须先上传或替换为可访问链接。

## 状态与归档

建议小明项目沿用这些状态文件概念，但放在本项目 `state/` 目录：

- `state/.daily_broadcast_state.json`：每天每类播报是否已发送，以及所有模块共享的内容去重记录。
- `state/.dadao_message_state.json`：大道消息各来源去重记录。
- `state/.learning_inventory.json`：三分钟知识卡库存和已发送状态。

建议归档到：

- `docs/心理学冷知识.md`
- `docs/三分钟知识卡.md`
- `docs/大道消息.md`

归档规则：

- 同一天同类内容不要重复写入。
- 早安只归档心理学冷知识，不归档完整早安。
- 三分钟知识卡归档完整卡片。
- 大道消息归档完整消息和原文链接。

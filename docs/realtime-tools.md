# 小明实时查询能力

## 目标

小明不能只靠模型记忆回答实时问题。遇到天气、日期时间、明确要求搜索或新闻类问题时，先查真实数据，再用简短口语回复。

## 当前已接入

### 时间日期

触发示例：

- 现在几点
- 今天几号
- 今天星期几

数据来源：

- 本机时间
- 时区固定为 `Asia/Shanghai`

失败策略：

- 本地时间一般不会失败。

### 天气

触发示例：

- 今天北京天气如何
- 北京会下雨吗
- 要不要带伞
- 上海气温多少

数据来源：

- Open-Meteo Geocoding API
- Open-Meteo Forecast API

默认城市：

- `REALTIME_DEFAULT_CITY=北京`

回复内容：

- 天气状态
- 当前温度
- 当日最低/最高温
- 降雨概率
- 是否建议带伞

失败策略：

- 如果实时接口没拿到，不编天气。
- 回复“天气接口没拿到，建议看手机天气”。

### 网页搜索

触发示例：

- 帮我查一下 OpenAI 最新新闻
- 搜一下某家公司最新消息
- 今天有什么 AI 新闻
- 最新 AI 消息

数据来源：

- Bing 搜索页
- 本地解析前两条搜索结果

回复内容：

- 最多 2 条结果
- 标题
- 摘要
- 链接

失败策略：

- 搜索接口超时或无结果时，不编内容。
- 回复“搜索接口没拿到可用结果，请换更具体关键词”。

## 当前配置

```bash
REALTIME_TOOLS_ENABLED=true
REALTIME_DEFAULT_CITY=北京
REALTIME_SEARCH_ENABLED=true
REALTIME_SEARCH_TIMEOUT_MS=20000
```

## 处理顺序

```text
用户消息
→ 判断是否需要回复
→ 判断是否命中实时工具
→ 命中则查真实数据并直接回复
→ 未命中才交给 Kimi
```

## 迁移注意

- 实时查询能力在 `bot.js` 内，不在播报脚本内。
- 天气播报和群聊问天气现在是两条链路，但都使用真实天气数据。
- 搜索工具目前是无密钥方案，长期稳定性弱于正式搜索 API。
- 搜索前会清理“帮我查一下”“播报”等触发词，避免把“你/帮我”这类词当成查询主体。
- 单独出现“最新”不再触发搜索，避免“最新要求”“最新配置”等内部规则问题被误当作网页搜索。
- 如果迁移到服务器，必须确认服务器能访问 Open-Meteo 和 Bing。
- 后续如果接入付费或带额度的搜索 API，必须先更新本文档和 `.env.example`。

## 验证命令

```bash
node bot.js --reply-text '今天北京的天气如何，会下雨吗'
node bot.js --reply-text '现在几点，今天星期几'
node bot.js --reply-text '帮我查一下 OpenAI 最新新闻'
node bot.js --self-test
```

成功标志：

- 天气问题返回温度和降雨概率。
- 时间问题返回北京时间。
- 搜索问题返回标题、摘要和链接，或者明确说明搜索接口没拿到。
- `--self-test` 返回 `self-test passed`，用于确认句末 @、贴着中文的 @、系统提示词文件读取、搜索词清洗和“最新要求”不误触发搜索没有回退。
